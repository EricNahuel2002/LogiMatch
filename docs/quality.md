# Quality

Siempre que sea posible:

- Nombres claros.
- Métodos pequeños.
- Clases con una responsabilidad.
- Código autoexplicativo.
- Evitar comentarios innecesarios.
- Nullability habilitado.
- Async/Await cuando corresponda.
- Validar entradas y manejar errores apropiadamente.
- Mantener el código desacoplado.
- Validar entradas.
- Manejar errores.
- Registrar logs.
- Pensar en escalabilidad.
- Escribir tests apropiados.

## Testing

Framework previsto:
- xUnit

Los tests deben acompañar funcionalidades relevantes y evitar convertirse en una excusa para introducir complejidad innecesaria.

## Base de datos

- Entity Framework Core.
- Migraciones mediante EF Core.
- Procedimientos almacenados solo con una razón clara y explicada.
